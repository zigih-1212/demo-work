# Q2.4 — Fitting and Measurement of Decimal Counting

## Context

This document provides context for measuring decimal counting in geometry processing, with one basic sample of how decimal counting can be computed via decomposition.

## Implemented Homoethic Counting

### Automated Homoethic Hierarchy

The detection geometry uses an automated semantic approach: the semantic domain (geometry) is organized into "Homoethic" groups when expressing the groups as signs of varying hierarchy levels (1 to $\lambda$). This approach depends on capabilities, not pure geometry, to decide which groups exist (whether "HMO-350" exists at some level). If the semantic domain is fixed as the geometry domain, then the groups are predefined.

### Structure

```
Level 1: Numbers (Maximum and Minimum)
Level 2: Ratios
Level 3: Proportions
Level 4: Functions
Level 5: Homothetic transforms
Level 6 to 50: Extended transformations
```

### Implementation

Homoethic groupings provide a structured way to represent decimal counting at each level:
- Quantitative base (some fixed level)
- Output of robot operations
- Derived functions
- Transforms on each level

### User-driven Measurement Approach

The implementation follows a user-driven methodology where the user accepts all calculations (semantic information), and the System only maintains the database via standard ORM hooks. This approach allows flexibility in computation options while maintaining data integrity.

## Decimal Counting

Decimal counting is extracted from geometry using the same approach: use the semantic domain of geometry, identify what groups exist, and then measure the number of groups (counts) that match the semantic requirement.

For example, if we have three teeth in a scan, the count is 3; if we have two incisors and three canines, the count is 5.

### Basic Sample of Decimal Counting via Decomposition

```javascript
function counting_via_decomposition(a, b) {
    // Decompose the given parameter(s) into known binary units
    const small_unit = 0.5
    const medium_unit = 2.5
    const big_unit = 50

    const a_decomposed = decompose_number(a, small_unit, medium_unit, big_unit)
    const b_decomposed = decompose_number(b, small_unit, medium_unit, big_unit)

    const count_a = a_decomposed.reduce((acc, val) => acc + val, 0)
    const count_b = b_decomposed.reduce((acc, val) => acc + val, 0)

    return [count_a, count_b]
}

function decompose_number(n, small_unit, medium_unit, big_unit) {
    const result = [0, 0, 0]
    if (n >= big_unit) {
        result[2] = Math.floor(n / big_unit)
        n = n % big_unit
    }
    if (n >= medium_unit) {
        result[1] = Math.floor(n / medium_unit)
        n = n % medium_unit
    }
    result[0] = Math.floor(n / small_unit)
    return result
}
```

**Notes**:
- This is a basic sample for demonstration
- In production, the implementation would be more sophisticated, using actual geometry data
- The semantic approach allows for flexibility in computation options
